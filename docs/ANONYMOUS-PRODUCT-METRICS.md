# Private product metrics on Vercel Hobby

Scope updated 2026-10-29 at the owner’s explicit request: replace aggregate-only reporting with detailed tab visit history, exact submitted calculator values, date/country filters and source attribution. Older aggregate-only notes describe the previous release, not the current scope.

## Current collection

Version 2 first-party events include a random per-tab visit ID (sessionStorage, memory fallback), client event time and server receipt time, allowlisted pathname, query/fragment-free referrer, safe UTM source/medium/campaign, broad device category, and approximate Vercel network country/region/city. Explicit completed calculations additionally store exact submitted test score/GPA and selected test/program/round, status and estimated probability. Main calculations, report rendering, generated PDF/download initiation, GPA actions, navigation/contact clicks and observed booking callbacks share the tab visit context. No every-keystroke capture or session video replay.

No new popup or cookies are added. Existing opt-out and browser DNT/GPC suppress collection. A no-cookie design alone does not establish a legal exemption for detailed analytics/sessionStorage; do not describe it as anonymous or universally consent-exempt. The privacy page describes actual collection. No fingerprint, raw IP, name, email, free text, payment details, GPS, query strings or URL fragments are retained. Network geolocation is approximate and VPNs can change it. Referrers can be absent. Tab IDs are not reliable unique-person identifiers, and cross-tab/new-device visits cannot be unified.

## Storage, limits and access

Existing dedicated Chance Me Upstash Free database, EU Frankfurt, provider-managed Vercel credentials. No new service/account/secret is required. Version 1 cached clients keep aggregate compatibility. Version 2 exact records and counters update atomically using Redis CAS/Lua; replayed event IDs do not duplicate counts. Aggregate keys expire within90days, replay keys within48hours, detailed journal keys within30days. No raw body logging. Maximum1000 detailed actions per UTC day and1000 batches/day; reports flag truncation. Frontend batches are bounded to16events/8192bytes; collection errors never block calculations/PDFs. Blockers, opt-out, dropped requests and throttling can undercount. No historical backfill.

The owner report script generates a private local file outside public/, mode0600, with real records, date/country/event/visit filters, sorting and grouped visit timelines. It is a snapshot, not an online public dashboard. `scripts/product-metrics-dashboard.mjs` serves fresh owner data at127.0.0.1:18791 only, refreshes60seconds, no CORS, denies cross-site/iframe requests and requires the exact loopback Host. Launch via approved project-scoped `vercel env run --environment development --project bocconi-chanceme --scope zielinskimarcins-projects -- node scripts/product-metrics-dashboard.mjs`. Tokens remain server-side in process memory. Stopping that process stops the dashboard; collection on production continues independently. Never deploy the dashboard as an unauthenticated public endpoint.
